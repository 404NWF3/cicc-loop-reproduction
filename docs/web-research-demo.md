# 网页研究演示与现场挖掘

2026-10-15。本次实现只提供网页内放映，按最新要求不提供 PPTX / PDF 下载入口。当前版本在本地验证，线上状态以 Railway 的部署记录为准。

## 页面与演示流程

`/presentation` 是 14 页研究演示，支持左右键、PageUp / PageDown、Home / End、F 全屏、N 讲稿、目录跳转和手机纵向阅读。页码保存在 URL 中，例如 `/presentation?slide=11`。第 13 页进入 `/mine`，实验页可以回到第 13 页。

内容依次为：研究问题、因子与交易时点、生成/审查/验证循环、五种搜索策略、联合门槛、FSA、报告的搜索规模、历史收益证据、信息来源集中、本地留出检验、市场拥挤、现场实验、研究结论。中金数据均标为用户论文转述的历史回测；本地 23 个入库因子的配对图直接读取 v2 归档指标，未构造报告中缺失的每日净值或迭代曲线。

来源数据为 `web/src/presentation/slides.json` 与 `local-results.json`；组件为 `pages/PresentationPage.tsx`。R2D3 只作为左右叙事排版的参考，未复制其图文或代码。照片、署名和授权清单见 `web/public/presentation/sources.json` 与网页「资料」面板。上传的参考 PPTX 超过文件传输工具的 32MiB 限制，未能读取；不声称按其具体页面进行设计。

建议现场演示：

1. 放映至第 13 页，点击「进入实时挖掘」。
2. 完整搜索使用默认「本地搜索 / 1,200 个候选」；短演示可选 36 个。默认时限 60 分钟，可改为 15 或 30 分钟。
3. 暂停并刷新，再继续，展示持久化检查点。
4. 选择一个归档种子，展示实际计算的净值和通过的门槛；再选择被拒候选，解释失败条件。
5. 展示入库中「新候选」的单独计数，回到第 11 页讨论留出退化。

## 计算边界

内置 StockNet 固定 commit 的 50 股开发期快照：2012-09-04 至 2015-12-31，837 个交易日，5 个 float64 OHLCV 面板，压缩后 **1,252,345 字节**。SHA-256 在首次载入时验证。2016 年以后的留出价格不随这个运行快照发布。复权沿用原实验，存在事后复权和股票池选择偏差。

本地模式先重新计算 6 个已知归档种子，再用开发期反馈做参数扰动、平滑或随机生成。种子明确标为「已知种子复算」，不能算作新发现。每个候选仍真实执行 DSL、时间对齐、自融资回测、费用和原 11 项门槛；首个因子的相关性标为不适用。

发现期为 2012–2013 年，按发现期 IC 冻结方向；2014–2015 年用于开发筛选。Top 20% 等权、下一日开盘执行、每 5 个交易日调仓、单边成本 0.1%，等权基准也扣费。图示相对净值每 5 日采样，指标由完整每日序列计算。网页现场结果只属于开发期，不产生新的独立样本外结论。

每任务至多 **1,200 个候选、每批至多 12 个、最长 3,600 秒**；网页默认 1,200 个、60 分钟。只有一个活跃任务和一个工作进程，候选计算限时 5 秒。暂停时间计入墙钟预算；暂停和停止在当前计算或模型请求结束后的检查点生效。

DeepSeek 模式逐批生成最多 12 个候选，再以独立上下文批量审查，然后逐条实际验证。下一批接收开发期结果反馈：失败类型、最近六个尝试、前三个开发期候选与冻结骨架，不读取留出期。审查上下文仅含公式与机制，不包含生成者的论证和此前绩效。固定使用已核实的 `deepseek-flash`，关闭思考模式。模型少返回候选时，下一批继续补充至目标或停止上限；不自动切换为本地搜索。旧版已生成的单批任务沿用原行为与冻结预算。

网页单次模型预算可选 **1 / 3 / 5 / 10 元**，默认 **5 元**，累计仍最多 **40 元**。停止上限是候选数、时间、单次模型预算、累计账本或存储额度中的任一项；预算不是预付费用，也不保证入库数量。模型审查通过仍需通过全部适用数值门槛；这个现场任务不是完整 E0–E7 消融实验。

候选使用游标增量读取，每次最多获取 100 条；页面每页展示 60 条，可翻页或跟随最新。运行计数在候选写入的同一事务中更新，历史数据库启动时自动补齐；状态轮询不会重新加载全部净值。模型原始响应单独归档并随研究 JSON 导出，检查点只保留当前批次。

## Railway 配置

最省资源的拓扑为现有 `Dockerfile` 内的一个 API + 一个 worker，同时提供静态前端。已分开部署的前后端也可以使用：

| 位置 | 配置 |
| --- | --- |
| 前端构建环境 | `VITE_API_BASE_URL=https://后端域名`，不包含 `/api/v1`；更改后重新构建前端 |
| 后端环境 | `LOOP_CORS_ORIGINS=https://前端域名`；多个精确来源用逗号分隔 |
| 网站登录 | 沿用 `LOOP_AUTH_USERNAME` / `LOOP_AUTH_PASSWORD`，生产必须配置；与付费演示口令分开 |
| 付费模式后端 | `DEEPSEEK_API_KEY` 与 `LOOP_RESEARCH_TOKEN`，后者为单独的演示口令 |
| 持久卷 | 沿用 `/data`，任务在 `/data/runtime`，累计预算账本也在卷内 |
| 预算账本 | Docker 默认 `LOOP_BUDGET_PATH=/data/deepseek.sqlite3`；本地默认共享 `artifacts/budgets/deepseek.sqlite3` |

未配置密钥或演示口令时，登录后本地搜索照常可用，付费按钮禁用。不要把 DeepSeek Key 写入任何 `VITE_` 变量；前端只提交单独的演示口令。创建、开始、暂停、停止、恢复付费任务均需正确口令；浏览页面不会发起模型请求。前后端分开时需先在后端域名登录，HTTP 与 SSE 携带认证；完整说明见 [Railway 部署](railway.md)。

网页累计账本限制为 **40 元 / 2,000 请求 / 5,000,000 tokens**，任一先到即停止；单任务还受所选 1–10 元限制。升级只迁移旧版默认的 60 请求 / 120,000 tokens，人民币上限、历史费用及未知请求均保留，不重置账本；自定义更严格限制和升级后主动收紧的限制仍生效。本次历史基线会带入新的持久账本，重复启动不会重置。保持单实例和持久卷；迁移时一起迁移账本。请求发出前持久化预留；网络结果未知时保留预留，进程中断后的未知模型请求不会静默重发。

运行任务和结果属于共享课堂演示空间，不提供多用户隐私隔离。网站登录后可以启动无模型费用的本地任务，仍受单任务、计算时间和存储上限限制。
